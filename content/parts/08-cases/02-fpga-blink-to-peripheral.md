## 一句话定义

FPGA 入门路径是从翻转一个 LED 开始，再把同一套时钟、约束和管脚分配，逐步换成 UART、SPI、I2C 等真实外设，从而在可反复烧写的器件上练习「控制器 + IO + 驱动」。

## 作用与功能

点灯看起来幼稚，其实已经覆盖数字设计最小闭环：时钟、复位、计数器或状态机、管脚约束、比特流下载和板上观察。LED 是 GPIO 的特例——控制器可以是几行 RTL，PHY 就是 IO 标准（3.3 V CMOS）。下一步不要急着上 PCIe，而是把 GPIO 换成有协议的低速口：UART 打印证明时钟频率和波特率一致；SPI 读板上 Flash ID 证明主从时序和管脚映射；I2C 扫传感器地址证明开漏与上拉。每一步都在练 FPGA 流程里最容易翻车的部分：约束文件、管脚电压、时钟向量子和板级原理图不一致。

软核 CPU 或厂商提供的硬核 MCU 可以再往上走：用软件驱动访问外设 IP，而不是手写状态机发 SPI。这时 FPGA 板变成迷你 SoC 实验室。成功标准从「灯闪」变成「枚举到器件并稳定传输」。调试手段从盯 LED 变成串口日志和逻辑分析核。

## 在全流程中的位置

这条路径对应 FPGA 设计流程的全循环：RTL → 综合实现 → 管脚与时序约束 → 下载 → 板级调试。它也是 ASIC 验证工程师熟悉协议落地的安全沙箱，不必等流片。做完低速外设，才具备加 MIG（DDR）、高速收发器的前提，因为约束和时钟纪律已经建立。每一级升级只改一个变量——先换外设、再加软核、最后才动时钟频率——否则灯不闪时说不清是约束错了还是协议状态机错了。

## 典型应用场景

课程实验：闪灯、数码管、串口回环、SPI 屏幕。产品原型：先在 FPGA 上跑传感器融合算法，确认 I2C/SPI 时序，再迁 ASIC。产线夹具：FPGA 充当协议转换，用 GPIO 和 UART 控制待测板。兴趣开发：开源软核 + 开源外设 IP，全部公开文档即可复现。无论哪条场景，都把「原理图、约束、波形」三件对照物准备好，比再买一套教程更有效。

## 一个小例子

第一周：计数器分频翻转 LED，约束对上开发板丝印。第二周：同一时钟域实例化 UART，把「hello」打到 PC 终端，修正约束里的实际晶振频率。第三周：用 SPI 主控制器读 Flash JEDEC ID，逻辑分析核抓 MOSI/MISO。若 ID 不对，对照原理图查片选极性和 IO 电压，而不是先怀疑「SPI 模式字段」。这条升级线把板级低速接口章的选型直觉变成手上的波形。

## 本节知识点

- 点灯闭环：时钟、RTL、管脚约束、下载、观察，是 FPGA 的最小系统。
- LED 属于 GPIO；UART/SPI/I2C 是下一个复杂度台阶，仍在低速域。
- 大多数板级失败来自约束、电压和原理图，而不是协议理论。
- 软核加驱动后，FPGA 可当作迷你 SoC 来练集成。
- 先稳定低速外设，再上 DDR 或高速收发器。
- 开源核、开源 IP 与厂商开发板文档足够支撑入门，不必依赖付费课。
- 调试顺序：灯 → 串口 → 再挂总线外设，与 ASIC bring-up 同构。
