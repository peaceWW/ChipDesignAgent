## 一句话定义

PCIe、USB、Ethernet 是芯片出封装后的高速串行互连：各自用 Controller（含链路/事务逻辑）加高速 SerDes PHY，再由主机或固件驱动把通道呈现为设备、功能或网络接口。

## 作用与功能

这三族协议都把「宽而慢的并行总线」换成「少对差分线、高速率」，换来的是封装管脚更少、线缆或插槽可插拔、带宽可按通道扩展。PCIe 擅长芯片到芯片、板到卡的存储器语义访问，显卡、SSD、网卡都像一段可映射的地址空间。USB 擅长外设即插即用和供电，面向人插上就能用的设备树。Ethernet 擅长包交换组网，面向交换机、路由器和端到端的 IP 世界。三者都能跑很高速率，但软件模型和拓扑不同，不能只看 Gbps 数字互相替代。

芯片里的落地高度相似。数字控制器实现链路训练、流控、重传、拆组包；有的把事务层和链路层做成可综合 IP。PHY/SerDes 负责并串转换、均衡、时钟数据恢复，几乎总是硬核。驱动在 CPU 上枚举设备、配置 BAR 或描述符环、处理中断和 DMA。PCIe 常直接接到片上一致性或 AXI 互连，让对端 DMA 进主存；USB 和 Ethernet 也靠 DMA，但操作系统里的抽象是总线驱动加类驱动，或网络协议栈。

入门不要背 TLP 字段或 USB 描述符表。先问：这条口是给「扩展一块功能卡」、给「插上一个外设」，还是给「加入一张网络」。再看通道数、速率档和 PHY 供应商。

## 在全流程中的位置

规格决定要几条 PCIe、是否含 USB 主机/设备、有几口以太网及其速率。这会锁定 SerDes 数量、参考时钟、封装 Ball 和电源域。集成阶段把控制器挂到互连和中断控制器，PHY 落到指定 IO。验证用 VIP 做链路训练和压力流量。物理与封装要过通道损耗和串扰。软件在 FPGA 或硅后联调枚举。高速 IO 是系统芯片的「对外大门」，失败往往表现为枚举失败或偶发 CRC，而不是纯数字功能错。

## 典型应用场景

PC/服务器 CPU：多条 PCIe 根复合体下挂 GPU 与 SSD，另有以太网口做管理或数据面。手机：USB 做充电与数据，PCIe 有时挂 UFS 或调制解调，以太网少见。交换机芯片：大量 Ethernet MAC + SerDes，PCIe 只作主机管理口。工控网关：一口千兆以太网加 USB 调试，PCIe 可能完全没有。场景决定控制器数量，不决定分层结构。

## 一个小例子

主机要把 4KB 描述符交给 NVMe SSD。驱动把命令放到主存队列，写门铃寄存器；PCIe 控制器把存储器写/读事务送给 PHY，差分线上出现高速串行码流。SSD 端的 PHY 恢复比特，控制器解析事务并 DMA 读写自己的闪存控制器。USB 拷文件或以太网发数据包，只是换了控制器状态机和驱动栈，PHY 仍然是 SerDes。你在芯片平面图上看到的是「控制器块 + SerDes 列」，不是协议文档章节。

## 本节知识点

- PCIe/USB/Ethernet 都是 Controller + SerDes PHY + 驱动/协议栈。
- PCIe 偏芯片互连与存储器语义；USB 偏即插即用外设；Ethernet 偏组网发包。
- 带宽由速率档和通道数决定，但不能用带宽数字跨协议硬替。
- 高速 PHY 是硬核，决定封装、时钟和信号完整性预算。
- 软件枚举、DMA 和中断是通路点亮的最后一公里。
- 验证重点常在链路训练、流控和错误恢复，而不是应用层字段。
- 选型先看拓扑和软件模型，再看速率与通道。
